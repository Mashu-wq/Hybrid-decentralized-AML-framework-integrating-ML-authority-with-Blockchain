This file explains how to start the entire system from scratch on a fresh
terminal session, including infrastructure, all Go microservices, the Python
ML service, the analytics service, and the Streamlit dashboard.

────────────────────────────────────────────────────────────────────────────────
PREREQUISITES (must be installed once)
────────────────────────────────────────────────────────────────────────────────

  - Docker + Docker Compose  (for PostgreSQL, MongoDB, Redis, Kafka, Vault, etc.)
  - Go  1.22+                (for building/running Go microservices)
  - Python 3.12              (ML service + dashboard — venv is at dashboard/.venv)
  - git                      (project is version-controlled)

  The Python virtual environment is already set up at dashboard/.venv.
  All Python packages (FastAPI, Streamlit, torch, lightgbm, etc.) are installed
  there. No pip install needed unless you're setting up from scratch.

  The Go binaries are pre-built in the bin/ directory.
  Run  make build  only if you have changed any Go service source code.

────────────────────────────────────────────────────────────────────────────────
QUICK START  (all in separate terminals, in this order)
────────────────────────────────────────────────────────────────────────────────

  TERMINAL 1  — Infrastructure (Docker)
  TERMINAL 2  — Go microservices
  TERMINAL 3  — Analytics service (separate because of env var requirement)
  TERMINAL 4  — ML service (Python)
  TERMINAL 5  — Streamlit dashboard

────────────────────────────────────────────────────────────────────────────────
STEP 1 — Start Infrastructure (Docker Compose)
────────────────────────────────────────────────────────────────────────────────

  Run in the project root:

    make infra-up

  This starts:
    - PostgreSQL    :5433   (fraud_detection DB)
    - MongoDB       :27017  (enriched_transactions)
    - Redis         :6379   (velocity windows, JWT cache)
    - Zookeeper     :2181
    - Kafka         :9092   (transactions.raw, alerts.created topics)
    - HashiCorp Vault :8200 (AES-256-GCM PII encryption)
    - Jaeger        :16686  (distributed tracing)
    - Prometheus    :9090   (metrics)
    - Grafana       :3000   (dashboards)
    - MLflow        :5000   (model experiment tracking)

  Wait ~30 seconds after this command before proceeding.

  Verify everything is up:

    make health

  All entries should show OK. If Kafka or Vault shows DOWN, wait 20 more
  seconds and run  make health  again.

  Optional dev tools (Kafka UI, pgAdmin):

    docker compose --profile dev-tools up -d

────────────────────────────────────────────────────────────────────────────────
STEP 2 — Apply Database Migrations
────────────────────────────────────────────────────────────────────────────────

  NOTE: The Makefile's  make migrate  target has a wrong path and does nothing.
  Apply migrations manually with the commands below (only needed ONCE on a
  fresh database).

  Check if tables already exist:

    PGPASSWORD=iam_user psql -h localhost -p 5433 -U fraud_user -d fraud_detection \
      -c "\dt kyc.*" -c "\dt public.fraud_alerts" 2>/dev/null

  If tables exist, skip this step. Otherwise run:

    BASE="/home/mayesha-marzia-zaman/AML_fraud_detection (2)/AML_fraud_detection"

    # 1. KYC schema
    PGPASSWORD=iam_user psql -h localhost -p 5433 -U fraud_user -d fraud_detection \
      -f "$BASE/services/kyc-service/scripts/db/migrations/001_kyc_schema.sql"

    # 2. Alert schema
    PGPASSWORD=iam_user psql -h localhost -p 5433 -U fraud_user -d fraud_detection \
      -f "$BASE/services/alert-service/scripts/db/migrations/002_alert_schema.sql"

    # 3. Case schema
    PGPASSWORD=iam_user psql -h localhost -p 5433 -U fraud_user -d fraud_detection \
      -f "$BASE/services/case-service/scripts/db/migrations/003_case_schema.sql"

    # 4. Analytics views
    PGPASSWORD=iam_user psql -h localhost -p 5433 -U fraud_user -d fraud_detection \
      -f "$BASE/services/analytics-service/scripts/db/migrations/004_analytics_views.sql"

  DB credentials:
    host=localhost  port=5433  db=fraud_detection
    user=fraud_user  password=iam_user

STEP 3 — Start Go Microservices
────────────────────────────────────────────────────────────────────────────────

  All Go services can be started with a single command:

    make run

  This runs  scripts/run-all.sh  which starts these services in the background
  and writes logs to  logs/<service>.log:

    Service              HTTP Port   gRPC Port
    ─────────────────    ─────────   ─────────
    encryption-service   —           :50066
    iam-service          :9000       :50060
    kyc-service          :9001       :50061
    transaction-service  :9002       :50062
    alert-service        :9003       :50063
    case-service         :9004       :50064
    blockchain-service   :9005       —
    api-gateway          :8080       —

  Press Ctrl+C to stop all services when done.

  To start a single service manually (e.g. for debugging):

    cd services/iam-service && go run ./cmd/server/main.go

  To check service logs in real time:

    tail -f logs/kyc-service.log

────────────────────────────────────────────────────────────────────────────────

  The analytics-service needs MONGO_URI set explicitly with credentials.
  Run this in a dedicated terminal from the project root:

    cd "/home/mayesha-marzia-zaman/AML_fraud_detection (2)/AML_fraud_detection"

    export POSTGRES_PASSWORD=iam_user
    export POSTGRES_PORT=5433
    export POSTGRES_DB=fraud_detection
    export POSTGRES_USER=fraud_user
    export INTERNAL_JWT_SECRET=K9xT2mQ7vL4pNz8RwY1cHd6FaSb3JeUt
    export MONGO_URI="mongodb://mongo_user:changeme_strong_password@localhost:27017/fraud_detection?authSource=admin"
    export MONGO_DB=fraud_detection

    ./bin/server

  You should see:
    INF  PostgreSQL connected
    INF  MongoDB connected
    INF  analytics-service ready  http_port=9006

  Verify it's running:

    curl http://localhost:9006/health
    # Expected: {"status":"ok","checks":{"mongodb":"ok","postgres":"ok"}}

  Why not  make run  for this service?
  The run-all.sh script starts analytics-service with  go run, which picks up
  the .env file automatically. The pre-built binary requires the env vars to be
  exported explicitly. Either approach works — choose whichever is simpler.

  Alternative (using make run for all services including analytics):

    make run     ← this handles env vars automatically via .env

STEP 5 — Start ML Service  [SEPARATE TERMINAL]
────────────────────────────────────────────────────────────────────────────────

  The ML service uses the Python virtual environment at  dashboard/.venv.
  Run from the project root:

    cd "/home/mayesha-marzia-zaman/AML_fraud_detection (2)/AML_fraud_detection"

    source dashboard/.venv/bin/activate

    # Register the ml/ package so 'import ml' works
    pip install -e . --quiet

    # Start the ML service (FastAPI on :8000, gRPC on :50051)
    cd services/ml-service
    PYTHONPATH="/home/mayesha-marzia-zaman/AML_fraud_detection (2)/AML_fraud_detection" \
    MODEL_ARTIFACT_PATH="/home/mayesha-marzia-zaman/AML_fraud_detection (2)/AML_fraud_detection/ml/artifacts" \
    python main.py

  You should see:
    INFO  starting fraud-detection-ml-service v1.0.0 (env=development)
    INFO  gRPC server started on port 50051
    INFO  Uvicorn running on http://0.0.0.0:8000

  Verify it's running:

    curl http://localhost:8000/health
    # Expected: {"status":"serving","loaded_models":["lightgbm","random_forest",...]}

  Note: The model comparison endpoint also works without trained .pkl files —
  it returns the static Elliptic benchmark results from the training run.

STOPPING EVERYTHING
────────────────────────────────────────────────────────────────────────────────

  1. Ctrl+C in each terminal (services, analytics, ML, dashboard)

────────────────────────────────────────────────────────────────────────────────
COMMON TROUBLESHOOTING
────────────────────────────────────────────────────────────────────────────────

  Dashboard shows "Service unavailable"
  → Check that the relevant Go service is running (make run)
  → Check logs/  directory for error output

  Analytics page shows 404 errors
  → The old analytics-service binary doesn't have the HTTP routes.
  → Rebuild: go build -o bin/server ./services/analytics-service/cmd/server/
  → Then restart following Step 4.

  ML service fails to start with "No module named 'ml'"
  → Run:  pip install -e .   from the project root (with .venv active)

  ML service fails with GNN RuntimeError (state_dict mismatch)
  → This is a known issue with the GNN checkpoint. The service will still start
    and work — only the GNN model will be unavailable. Other models load fine.

  "Port already in use" errors
  → Find the process: ss -tlnp | grep <port>
  → Kill it: kill <pid>

  Blockchain page shows "Service offline"
  → Start Fabric: make fabric-up && make chaincode-deploy
  → This is optional; all other pages work without Fabric.

  KYC / Alert / Case service returns 500 errors
  → Database tables may not exist. Apply migrations (Step 2 above).

  PostgreSQL connection refused
  → Docker container not running. Run: make infra-up

  Kafka connection errors in transaction-service logs
  → Kafka takes ~60 seconds to fully initialize after  make infra-up.
    Wait and retry.
